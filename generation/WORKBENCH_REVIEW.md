# 工作台打开体验复核

2026-11-12。

## 问题与修复

| 级别 | 发现 | 处理 |
|---|---|---|
| P1 | 原交付只有 HTML 文件链接；聊天/编辑器如何打开该文件取决于宿主，源码编辑器入口与浏览器预览入口没有区分。此前测试覆盖浏览器运行，未覆盖交付入口。 | 增加项目根目录 `打开项目工作台.cmd`，启动或复用本机服务并明确打开浏览器；本次也通过 Codex 浏览器面板工具提交了网页预览请求。 |
| P1 | 文件形式的证据链接依赖 `file://` 和文件默认打开方式，缺少统一可读预览。 | 本机服务对工作台实际引用的证据文件提供只读 HTML 预览，包含返回入口。 |
| P2 | 页面在窄预览窗口仍默认使用侧边导航及100%地图宽度，第一次打开需要横向找内容。 | 1100px 以下使用顶部横向导航；1200px 以下默认按可用宽度缩放。保留手动缩放和节点详情。 |
| P2 | URL哈希更新依赖宿主允许 `history.replaceState`。 | 对哈希更新单独容错，避免宿主限制影响模块运行。 |

## 验证记录

- Chrome 从 HTTP 用户入口实际加载全部六个视图，主要交互及 SVG 导出解析通过。
- 600/900px 窄窗口：页面无水平溢出，初始地图适合可用宽度；900px截图已复核。
- 首页、工作台、功能清单、工作日志和脚本证据返回200、UTF-8 HTML。
- 重复启动复用相同服务 PID。
- 非引用文件及路径穿越请求返回404；服务仅绑定本机地址。
- 本地服务端口优先8765，冲突时在8766–8785寻找可用端口；启动器使用实际端口。

收据：`project-workbench.check.json`、`workbench-entry-check.json`。服务日志：`workbench-server.log`。

Codex面板打开工具返回 `queued`，因此这里只记录已提交面板预览请求；用户侧面板是否实际显示，由宿主完成队列后确认。本机浏览器HTTP加载和交互已经独立验证。
